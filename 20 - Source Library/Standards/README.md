# Standards Register

Every external standard the Workbench rests on, one entry each.

## Why this exists

A scan of the vault on 2026-10-09 found **25-odd distinct standards cited across
200+ places** — in slide text, in course data, in engine code, in the Process
Core. Each citation carried its own justification inline, in prose, wherever it
happened to appear. That is expensive to write, impossible to keep consistent,
and it answers the wrong question: it tells you what *this* slide thinks, not
what the house position is.

It also hid something. **`ISA-5.1` is cited 33 times and Emerson does not hold
it** — confirmed against the Information Center's own ISA listing, which carries
5.2, 5.3, 5.4 and 5.5 but not 5.1. Thirty-three claims whose source nobody here
can produce if asked. No inline citation would ever have surfaced that, because
each one looked fine on its own.

## The inversion

**An artifact carries an identifier and a locator. Nothing else.**

```
ISA-5.5 §3.3.2          ← this is a complete citation
ASME B36.10M, Sch 40    ← so is this
```

**The register carries everything else, once**: what the standard is, which
edition, whether we hold it and by what route, what we have actually read of it,
what rests on it, what we deliberately did *not* take from it, and what the
copyright permits.

So:

| you want to | you do |
|---|---|
| **explain** a choice | open the entry |
| **defend** it | the entry has the edition, the clause, the access route and the reasoning, written once |
| **pull provenance** | the entry's `used-by`, which is generated by scanning, not kept by hand |

## The honesty fields

Two fields exist because the alternative is a register that flatters itself.

**`holding`** is not a yes/no.

| value | means |
|---|---|
| `confirmed` | a specific document has been opened and is on hand |
| `publisher-licensed` | Emerson's enterprise agreement covers this publisher, but **this document has not been checked** |
| `not-held` | established absent — a real exposure, not a to-do |

`publisher-licensed` is the honest answer for most entries here. Emerson's
Intertek agreement covers ASME, FCI, IEC, ISO, API and more, and that is a
different claim from "we have read this and can produce it."

**`read`** records what has actually been opened, clause by clause where it
matters. An entry may legitimately say *nothing* — cited but never read is a
real and common state, and writing it down is the point.

## Rules

1. **A citation in an artifact is an id plus a locator.** Prose justification
   belongs here, not there.
2. **Never invent an entry's content.** If a standard has not been read, `read`
   says so and `summary` stays empty. A register that guesses is worse than no
   register.
3. **Copyrighted text is not reproduced.** Entries describe, cite clause
   numbers, and record constraints. No standard's pages, figures or drawings
   enter this repository — see `isa-5.5.md` for the worked example.
4. **`used-by` is generated.** Do not hand-edit it; run the check.

## The check

```
node "20 - Source Library/Standards/check-standards.js"
```

It scans the vault for citations, resolves each against an entry, and refreshes
every `used-by`. It fails when a citation has no entry, and warns when an entry
is cited nowhere — the second is how a register rots quietly.

It is a vault-wide scan, so it is deliberately *not* bolted onto LPE's build or
the Process Core's tests: neither of those owns the vault, and a check that
reaches outside its own layer is the thing both of them exist to prevent.
